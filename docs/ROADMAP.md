# AI Spend Hub 产品路线图（动态维护）

更新时间：2026-10-09。版本号表示计划里程碑，不代表所有功能已经发布或验收。

## 产品原则

1. **现金流唯一口径**：订阅/充值/已支付 API 发票计入现金流；积分余额与 token 用量仅用于辅助指标，不能重复计费。
2. **来源可追溯**：自动采集须保留供应商、票据来源、稳定外部编号、原始金额/币种与换算快照；不保存未经必要脱敏的完整邮件、银行卡信息或 API 密钥。
3. **先审核后入账**：机器解析得到的内容先进入候选池，确认支付事实后才批准，不以“检测到邮件”直接认定扣款。
4. **单用户本地优先**：优先 NAS 内网部署、SQLite 与 JSON/SQLite 备份；任何第三方集成都必须明确授权、可断开、可停用。
5. **测试与可回退**：每次变更补测试、CHANGELOG/STATUS；通过 PR 合入稳定分支；数据库迁移必须保留旧数据。

## 风险与边界

- 邮件、银行账单、第三方账单接口授权 **目前均未连接**；不采集任何用户数据。
- 自动导入 `POST /api/transactions/import` 仍是针对“已核实账单”的直写接口，**来源不可信的自动解析器应使用候选 API**。
- `GET/PUT /api/state` 与现有 JSON 备份只包含主账本；审核队列在独立 SQLite 表中，使用 SQLite Online Backup 方式备份整个数据库。升级和恢复前务必另存数据库备份。
- 当前为单用户内网工具，令牌授权没有多用户角色或分级权限；不要直接暴露到公网。
- 本路线图不是持续后台执行任务的证明：每一轮实际完成的代码以 Git 提交、测试日志和状态文件为准。
